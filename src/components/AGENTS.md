- Day, 3-Day, and Week timed cards use the shared header-collision layout in calendar-layout.ts; stack priority follows deterministic occurrence order within each body-overlap cluster. Why: protect later headers without changing true event times.
- Desktop/tablet Calendar Day renders only WeekView; the agenda list stays on Today. Why: the embedded strip squeezed the timeline.
- Mobile Day/3-Day: touch-action none + single-axis gesture controller in use-day-strip.ts (axis lock, glide, gutter-aware snap). Why: native pan moved both axes.
- Phone Month uses MobileMonthView with fixed compact MonthView/date heading and a bounded agenda-only scroller whose height is the flex space left between the day heading and the phone navigation (no fixed cap); passive native listeners isolate agenda gestures without blocking scrolling or clicks. Shared occurrence expansion, colors and openOccurrence remain; larger screens retain MonthScrollView. Why: readable narrow cells, more event rows, isolated gestures, unchanged data/access rules.
- Nonrecurring timed occurrences retain original timestamps and keys; phone Month buckets them with occurrenceOccursOnDay using end-exclusive overlap. Why: show overnight continuations without inventing duplicate occurrences or shifting recurrence dates.
- Schedule Builder Review waits for serialized successful draft saves until the latest local snapshot is clean; card-title clicks are suppressed during drag gestures. Why: prevent stale previews and accidental editor opening after drops.
- Schedule grid hides originals represented by a draft using occurrence key/start or original-date split lineage, never destination date; confirmation stays in final Review. Why: one final card without hiding separate recurring shifts.
- Schedule Builder dates before the household's today are view-only in the grid, and planPublish(today) blocks changes touching them server-side; unchanged published past shifts stay unchanged. Why: historical corrections belong to Timesheets.
- Schedule Builder workspace renders for household roles canBuildSchedule accepts (Owner, Editor), never an owner-only check. Why: Activities, the server functions and the database policies all admit Editors, so an owner-only gate left them an empty page.
- Monthly grid parent work hours render only through workHourLines (real scheduled intervals); "Work hours unavailable"/"need review" notices live solely inside Check Coverage. Why: repetitive labels cluttered every cell while proving nothing, and incomplete-data warnings must not be lost with them.
- Schedule Builder shows one monthly hours summary (hoursSummaryLines: total after changes vs currently published, plus caregiver rows) — never a second proposed-vs-existing statistics block, and no "Private draft saved" status line. Why: two overlapping summaries made draft hours look like month totals; the header already shows draft/unsaved state.
- Check Coverage incomplete-data notes render as a small muted self-aligned popover trigger ("Some calendar data may be incomplete") holding the full explanation, never a full-width amber banner; per-day all-day review notes stay on their rows. Why: the banner dominated the dialog while the detail is only needed on demand.
- Review dialog lists operations as compact rows grouped into Modified / New / Removed, each with one group checkbox ("Confirm all changes" / "Confirm additions" / "Confirm removals") that supplies the existing per-operation confirmation ids; empty categories show no control, and conflicts, stale previews and unverified originals still block publishing. Why: per-shift checkboxes cluttered the review without adding a safeguard.
